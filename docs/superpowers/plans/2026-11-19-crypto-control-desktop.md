# Crypto Control Desktop

## Поточний стан

FastAPI вже запускає збір котирувань WhiteBIT у своєму життєвому циклі. `start.cmd` тримає Uvicorn у консолі. SQLite зберігає журнал і портфель, але вибірка оцінок для просадки зараз залежить від запитів `GET /api/v1/paper`, які інтерфейс робить кожні 30 секунд. Для пояснення зміни балансу попередня оцінка зберігається в пам’яті. Наявна пауза блокує ручний старт покупок.

## 1. Єдиний фоновий процес · середня складність

- Додати окрему точку входу ядра, яка запускає наявний FastAPI в одному процесі Uvicorn на `127.0.0.1:8000`. Використати абсолютний шлях до чинної SQLite. Існуючий `start.cmd` спрямувати на ту саму точку входу.
- Захопити блокування Windows, прив’язане до канонічного шляху SQLite, до відкриття бази. ОС звільняє блокування після виходу процесу. Другий запуск перевіряє ідентичність чинного ядра. Сторонній процес на порту дає зрозумілу помилку.
- Додати локальний журнал, перевірку готовності й окрему команду штатної зупинки, яка завершує цикл Uvicorn і зупиняє фонові задачі. Під час завершення нові операції не починаються.
- У Планувальнику завдань Windows передбачити явне ввімкнення автозапуску для поточного користувача після входу, `IgnoreNew`, обмежені повторні спроби після збою та відсутність ліміту тривалості задачі. Штатний вихід завершується з кодом 0. Передбачити команду вимкнення автозапуску. [Планувальник Windows](https://learn.microsoft.com/en-us/windows/desktop/taskschd/task-scheduler-schema)
- Перевірка на тестовій SQLite. Одночасно запустити два екземпляри, завершити ядро штатно, окремо імітувати збій і перевірити перезапуск без дублювання. Перевірити вхід у Windows та конфлікт порту. Ризики — помилки шляхів, повторні перезапуски та залишені дочірні процеси.

## 2. Збереження оцінок у фоні · середня складність

- Винести запис оцінки з HTTP-запиту у фонову задачу FastAPI. Кожні 5 хвилин ядро отримує потрібні книги, розраховує оцінку наявним кодом і зберігає її транзакційно. Один запис на інтервал UTC, зі свіжістю джерел і ревізією портфеля. Перед міграцією зробити та перевірити копію SQLite.
- Маршрут портфеля повертає актуальні записи журналу та останню збережену оцінку з її часом. Якщо ревізія змінилася після продажу, оцінка позначається як така, що передує операції. Застарілі котирування, сон ПК і відсутність мережі позначаються як прогалини, без відтворення пропущених оцінок вигаданими цінами. Порівняння балансу після перезапуску використовує дві збережені оцінки.
- Перевірка. Закрити всі клієнти, дочекатися двох циклів, перезапустити ядро й звірити оцінки. Перевірити збій WhiteBIT, сон і продаж під час розрахунку. Ризики — паралельний запис, застаріла оцінка після угоди та зміна частоти вибірки просадки.

## 3. Власне вікно Windows · середня складність

- Зібрати тонкий `CryptoControl.exe` на WinForms із WebView2, який відкриває чинний локальний інтерфейс. Використати системний WebView2 Evergreen Runtime і передбачити повідомлення за його відсутності. Вікно звертається лише до свого локального ядра, а за потреби просить Планувальник запустити його. Закриття вікна завершує лише процес інтерфейсу. [Розгортання WebView2](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution)
- Перша збірка для цього ПК використовує чинну Python `.venv` для ядра. Окремий інсталятор і пакування Python можна додати після перевірки. Створити ярлик робочого столу.
- Перевірка. Відкрити ярлик без Chrome, закрити вікно, дочекатися нового запису оцінки та відкрити вікно знову. Перевірити повідомлення при недоступному ядрі. Ризики — відсутній Runtime та неправильна адреса або версія ядра.

## 4. Керування майбутнім алгоритмом · середня складність

- Зберегти чинну паузу ручних покупок. Додати окремі стани алгоритму у SQLite. «Пауза алгоритму» тимчасово блокує його дії. «Аварійна зупинка алгоритму» блокує всі автоматичні купівлі й продажі до явного скидання, включно після перезапуску. Котирування, історія та ручне закриття залишаються доступними.
- Перевіряти дозвіл перед записом майбутньої угоди в тій самій транзакції. Перевірити паузу, аварійну зупинку й перезапуск на заглушці алгоритму. Автоматичні віртуальні угоди потребують окремого етапу та погодження стратегії.
- Зберегти FastAPI як єдину точку доступу до даних. Android і доступ з іншого пристрою розглядати окремим етапом.
